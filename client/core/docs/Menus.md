# Menus Service

## Goal

Create a complete Menus CRUD service in the backend application and its management pages in the frontend application.

The `Menus` worksheet represents the menu groups used to categorise items, such as:

* Breakfast
* Light Lunch
* Main Meals
* Sunday Roast
* Persian Specials
* Homemade Tarts & Cakes
* Hot Drinks
* Soft Drinks
* Alcoholic Drinks

Do not store products, variants, modifiers or prices in this worksheet. Those relationships will be handled later by the `MenuItems` service.

## Google Sheets structure

Use a worksheet named exactly:

Menus

The columns of the `Menus` worksheet must be in this exact order:

ID
Name
Description
SortOrder
IsActive
CreatedAt
UpdatedAt

## Field rules

### ID

* Required.
* Generated by the backend.
* Must be unique.
* Must never change after creation.

### Name

* Required.
* Trim leading and trailing spaces.
* Menu names must be unique using a case-insensitive comparison.

### Description

* Optional.
* Used for internal or frontend explanatory text.

### SortOrder

* Must be a non-negative integer.
* Default value is `0`.
* Used to control the display order of menus.

### IsActive

* Boolean value.
* Default value is `true`.
* Inactive menus must remain in the worksheet but must not appear in normal active-menu selections.

### CreatedAt

* Generated by the backend when the record is created.
* Must use an ISO 8601 timestamp.
* Must not change during updates.

### UpdatedAt

* Generated by the backend.
* Must use an ISO 8601 timestamp.
* Must be updated whenever the record changes.

## Backend requirements

Create the Menus service in the Apps Script backend.

The service must support:

* Create a menu.
* Get a menu by ID.
* List menus.
* Update a menu.
* Activate or deactivate a menu.
* Search menus.
* Pagination.

The list operation must support:

* Searching in the `Name` and `Description` columns.
* Filtering by active or inactive status.
* Pagination using the same request and response format as the existing Customers and Products services.
* Sorting by `SortOrder` first and `Name` second.

Do not physically delete menu rows. A delete or deactivate action must set `IsActive` to `false`.

Validate all input on the backend. Do not rely only on frontend validation.

Return clear validation and not-found errors using the same API response structure as the existing services.

## Backend structure

Use the completed Customers and Products services as technical references.

Create a menu-specific configuration file for values such as:

* Worksheet name.
* Column names.
* Default pagination size.
* Maximum pagination size.

Use the existing shared global configuration for values shared by all services, including `SPREADSHEET_ID`.

Do not create another copy of shared configuration values.

Do not unnecessarily rewrite or break the Customers or Products services.

Backend application path:

`./server/appScripts`

## Frontend requirements

Create the Menus management pages in the frontend application.

The frontend must include:

* Menus list page.
* Search input.
* Active-status filter.
* Pagination.
* Add-menu form.
* Edit-menu form.
* Activate/deactivate action.
* Confirmation before deactivation.
* Loading state.
* Empty state.
* Error state.
* Success and error feedback.

The list must display:

* Name.
* Description.
* Sort order.
* Active status.
* Available actions.

Use the existing Customers and Products frontend structure, API clients, components and design conventions as technical references.

Do not duplicate shared frontend logic when an existing reusable implementation can be used safely.

Frontend application path:

`./client/core`

## Scope restrictions

This task is only for the `Menus` service.

Do not implement the following services in this task:

* MenuItems
* Products
* ProductVariants
* ModifierGroups
* Modifiers
* ProductModifierGroups

Do not store prices or product relationships in the `Menus` worksheet.
